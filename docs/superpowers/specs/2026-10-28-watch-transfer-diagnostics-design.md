# Watch 与 iPhone 文件传输状态和诊断

## 目标

围绕新的传输单位——一条普通录音对应一个封存的 M4A 文件——统一 Watch 与 iPhone 的状态文案和诊断事件。帮助用户判断文件停在 Watch 本地、WatchConnectivity 系统队列、iPhone 收件箱、本机导入还是保存回执阶段。

## 状态语义

1. **Watch 待发送**：录音文件已封存并留在 Watch，本地传输尚未提交。
2. **系统排队 / 系统传输中**：文件已交给 WatchConnectivity；队列仅反映系统调度，不提供可靠的字节百分比。
3. **等待 iPhone 保存确认**：Watch 收到系统文件传输成功回调，但 iPhone 的持久保存回执尚未到达。
4. **iPhone 已保存**：iPhone 已将音频持久化并提交回执，Watch 收到回执后将该文件标记为已同步。
5. **失败 / 文件缺失**：明确标注故障所在设备与阶段，保留系统错误域/代码或应用错误类别。

手机实时可达性只描述即时消息通道。它不能单独代表后台文件传输是否可调度。Watch 上的待确认数量来自本地文件状态；iPhone 展示 Watch 状态快照时必须附更新时间。

## Watch 界面

- 录音列表逐条显示短 ID、录音时间、时长、文件大小，以及以上文件级状态。连续小时录音可额外显示录音组序号；该序号用于内容关联，不称为传输分片。
- “传输诊断”显示配对/激活状态、iPhone App 安装状态、即时可达性、系统文件队列中的传输中与排队数、待 iPhone 确认文件数、最近保存确认时间。
- 诊断页直接说明“系统队列是调度状态；收到 iPhone 保存回执才算同步完成”。
- 最近事件按时间倒序显示最多 20 条。

## iPhone 界面

- Watch 状态面板显示配对与 App 安装状态、即时可达性、Watch 报告的待确认文件数及其快照时间、本机最近保存时间。
- 最近传输事件显示最多 20 条，覆盖 Watch 文件回调、校验、写入本机收件箱、开始导入、本机持久保存成功/失败、保存回执提交/发送失败。
- 收件箱采用当前平面目录里的 M4A 与配套 JSON 录音信息展示待处理项，不再按旧长录音会话目录查 `manifest.json`。

## 可关联事件与隐私

- 两端事件使用相同的录音短 ID（UUID 前 8 位）关联；展示时间、事件阶段、录音类型/组序号、时长、字节数以及错误域/代码。
- 不记录音频、转写、完整 UUID、设备路径或坐标。
- 事件环形存储上限为 20 条，重启后继续可读；旧事件缺少短 ID 字段时允许显示。
- 模拟器与真机使用相同的 `transferFile` 整文件路径；小型保存回执使用 `transferUserInfo`。Apple 不支持在模拟器中使用这两种后台传输 API，因此模拟器只能检查录音、封存和界面，完整传输与回执须在配对真机验证。

## 不再展示的旧状态

完全移除旧 `RecordingV2` 网络分片协议与实现：Watch 队列、iPhone 收件器、握手/能力协商、分片回执、结束标记、撤回消息、旧 V2 快照和数据库投影。连续小时文件仍各自作为完整 M4A 上传；其组 ID、序号和 iPhone 本机录音处理使用的文件描述保留，用于本地内容关联与分析，不属于网络分片传输。

## 验收标准

1. Watch 列表能区分待发送、系统排队/传输、等待 iPhone 回执、已保存、失败和文件缺失。
2. Watch 的系统传输完成回调不会显示为已同步；只有收到 iPhone 保存回执才显示已同步。
3. iPhone 事件能看到文件收到、收件箱持久化、本机导入结果和回执提交结果，并能按同一短 ID 与 Watch 事件对应。
4. iPhone 手机可达性与后台文件队列/保存状态分开显示；状态快照显示更新时间。
5. 两端各保存并展示最近 20 条事件；日志不包含录音、转写、完整 UUID、路径或坐标。
6. 模拟器与真机调用相同整文件传输路径；完整的系统文件传输与回执验收在配对真机完成。
