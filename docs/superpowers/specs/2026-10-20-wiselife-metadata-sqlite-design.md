# WiseLife 第一阶段：业务元数据 SQLite 迁移

用户已确认 2026-10-20 数据架构说明及实施顺序。本阶段完成录音、图片、提醒元数据迁移；后续分别开展全文/分段向量检索、昨日回顾/跨日记忆。无需再次确认已批准的架构。

## 范围与存储

- 保留仓库公开调用接口、音频与图片文件路径、UUID、Watch 收件及确认流程。
- 默认真实 App 数据目录共用 `Application Support/WristNotes/Database/daybook.sqlite3`。任意测试/导入目录使用根目录内的独立 SQLite，不能误连真实用户库；可注入 `DaybookDatabase`。
- 使用系统 SQLite 现有事务、迁移标记、WAL 和保护机制。旧 v1 升级到 v2 时保留生活、对话、洞察、语义数据；新表必须有日期索引。
- 录音核心索引列支持 UUID、日期、类型、标题、全文、总结、时长、文件名查询。Codable 快照完整保留来源、说话人、转写段与版本等附加字段；投影与快照在同一事务写入并在读取时检查一致性。
- 图片记录和附件分别存关系表；每图 OCR 与错误信息、附件顺序、UUID 不变。提醒使用独立表，保留系统通知 ID。
- 大媒体不作为数据库 BLOB；API Key 不进入数据库。

## 一次迁移与失败恢复

- 每个领域首次打开时读取旧 JSON，验证后在同一事务写入记录和完成标记；重新打开不会再次导入。
- 原 JSON 字节保留用于恢复，迁移后不再作为运行时写入目标。坏 JSON、重复 UUID、约束失败导致整个领域迁移回滚并报错，不能静默初始化空库。
- 导入允许媒体缺失的合法元数据，以便后续重复传输修复音频；禁止路径越界/符号链接访问。
- 新写入只更新受影响记录；失败时保留原持久状态与内存状态，不发 Watch 成功确认。
- 录音删除写入墓碑与删行在同一事务完成；音频文件未删成功时，启动孤儿文件恢复必须跳过已删除 UUID。文件清理由后续启动重试，不得复活记录。
- 图片提交先保存文件再提交记录，失败清理本次新文件。删除元数据成功但文件未清理时，重启应能继续清理，且不会恢复成记录。
- 多个仓库实例不能通过旧内存快照覆盖新数据：录音/图片定点写入并从数据库读取当前值；提醒 replace 对基线执行乐观冲突检查。
- 媒体文件和系统通知不参与 SQLite 原子事务，保留现有协调器的失败补偿语义。

## 验收

通过真实临时 SQLite 与临时媒体测试：旧 JSON 全字段迁移、重开、幂等、旧 JSON 字节保留、坏数据失败可恢复、SQL trigger 强制中途失败回滚、删除不复活、Watch UUID 重传去重、多个仓库实例不丢写、索引查询计划；原仓库/提醒协调器测试继续通过。

不操作用户真机数据库，不改模型/设置 UI，不重新生成 Xcode 工程。只采用已有编译成员源文件，或在确有必要时精确新增项目引用。
