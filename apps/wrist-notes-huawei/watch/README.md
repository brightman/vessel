# GT 6 watch core

此目录目前是 **JS 核心逻辑**，没有可安装的 HAP，也未实现真实录音和 Wear Engine 适配。

- `core/recording.js`：轻点/长按互斥，0.45 秒进入闪念，少于 0.3 秒丢弃，上滑取消。返回动作意图，不能当作麦克风已启动。
- `core/transfer.js`：串行发送状态、应用级保存确认、重试、删除保护、3,000,000 字节分片规划。只有正确 ID、字节数和 SHA256 的 `stored` 回执才能改变上传状态。
- `tests/`：Node 纯逻辑检查，不依赖也不模拟手表硬件能力。

## 适配约束

1. 获取 GT 6 录音 API 前不创建静音文件、不伪造成功状态、不用手机采集替代手表采集。
2. 使用计时器单调时间驱动 `RecordingInteraction`；每个触摸序列只能有一个释放动作。
3. 原生录音成功回调后再显示正在录音。权限弹窗期间若松手，取消待启动的闪念；延迟回调必须校验会话 ID。
4. 录音文件与元数据写入完成后才加入队列。`TransferQueue.snapshot()` 必须由原生持久化层在每次状态迁移后原子保存，再调用 SDK。当前目录不含该持久化层。
5. 一次发送一份文件；分片应从文件流读取，不把长录音全部加载到 JS 内存。当前目录只有分片计划，没有切片读写或发送实现。
6. `transportFinished()` 仅表示等待手机回执；超时后调用 `retryUnacknowledged()`，带退避，不在无连接时循环重试。
7. 来自 SDK 的消息必须经过对端身份验证后才交给 `acknowledge()`。删除录音时同步删除自己的本地文件，不能删除手机副本。
8. `remove()` 仅更新队列；真实文件删除需要存储层提供原子或可恢复的事务。

运行：`node --test apps/wrist-notes-huawei/watch/tests/*.test.js`（仓库根目录）。
