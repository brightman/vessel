# 6 小时 42 分录音：真机数据与 Mac 分段实测

检查日期：2026-10-23。此报告使用从已连接 iPhone 复制的真实音频和 SQLite 数据，未上传音频或全文到云端。

## 结论

- iPhone 上是 **1 个旧版 `.m4a` 文件**，有效时长 **24,129.276 秒（6:42:09.276）**，大小 **99,523,276 字节**。这条录音没有按 10 分钟生成物理文件。
- 文件全程解码成功；文件散列与手机历史处理描述中的散列一致。没有发现手机文件少一小时或尾部不可解码的情况。尚未取得 Watch 原件，不能声称已完成 Watch 与 iPhone 的逐字节比对。
- Mac 重跑复现了手机的 **25 个 VAD 成功、56 个失败**。根因是实际 Core ML 输出 `1.0009765625` 被严格的概率上限检查拒绝。
- 修复这一数值边界后，**81/81 个 VAD 窗口成功**，覆盖整条录音；当前无人声分段规则得到 **1 个已完成、有全文的内容段**，范围 `00:00:00–06:42:09.276`。
- 这不代表录音只有一个话题。此 Mac 的 Foundation Models 返回 `unavailable(deviceNotEligible)`，主题推理、标题和摘要没有执行。

## 实测方法

1. 复制 iPhone 数据库、WAL/SHM 和目标音频；对数据库副本做 SQLite backup，`quick_check=ok`。
2. 检查原件时长、散列和完整解码。音频为 AAC、16 kHz、单声道；容器时长 `24,129.408` 秒，与有效帧时长差 `0.132` 秒。
3. 编译实际 Swift 生产代码 `BoundedAudioReader`、`OnDeviceSpeechActivity`、`AudioActivityReconciler`、`ContentSegmentation`、`ContentSegmentRepository`，在 Mac 本地调用。
4. 复用同一来源、音频散列和处理配置下，一代完整的 81 个成功 ASR 窗口；不将五代历史结果叠加。ASR 本次没有重新识别。
5. 对完整原音频重新执行 VAD，窗口核心最多 300 秒，前后上下文最多各 2 秒。用实际 SQLite 仓库提交分析并生成内容段。
6. 修复前后使用独立数据库副本、相同输入和同一代 ASR；音频原件未变。Mac 上的试验性任务恢复不改变手机的取消状态。

## 为什么没有自动拆成多段

当前规则是：**连续至少 600 秒，ASR 和 VAD 均成功，ASR 没有文字，VAD 持续确认无人声**。失败或不确定不能累计成无人声。

全文中最长无 ASR 文本区间为 `00:17:39.400–00:29:47.140`，长 **727.740 秒**。历史成功 VAD 在这一区间的证据为：

| VAD 分类 | 累计时间 |
| --- | ---: |
| 确认无人声 | 688.480 秒 |
| 不确定 | 31.694 秒 |
| 检测到人声 | 7.565 秒 |

这些无人声区间并不连续。整条录音经修复版重跑后，最长连续确认无人声仍为 **80.202 秒**，没有满足 600 秒阈值的区间。因此基础分段保留一个完整内容段符合当前实现。

VAD 检出人声并不证明一定是有效对话，也可能是背景声音误检；本次没有人工逐段听审，不能给出真实人声准确率。如果希望这种“长时间没有可读内容、夹杂零星疑似声音”的区间也能分段，应另行定义候选边界与容错策略，并保留原始音频及证据。

## 已发现的问题与优化

### 1. VAD 将 FP16 的微小上溢判为整窗失败

实测在原音频 `01:17:58`、`01:18:58` 起始的 30 秒推理块中，模型输出上限为 `1.0009765625`。所有掩码仍为合法的 0/1，概率均有限；这是比 1 多一个 FP16 步长的输出。

修复只允许这个有界的上溢并归一为 1。负值、非有限数、超过容差的值仍被拒绝。高概率且无活动掩码仍归为不确定，不会因此变成无人声。

新增回归先在原代码下因 `SpeechActivityError.invalidOutput` 失败，再在修复后通过。真实录音全量运行从 56 个失败窗口降到 0。

### 2. 同一音频因 iOS 沙盒路径变化重复建立处理任务

目标在同一配置下出现五代、共 **405 个窗口任务**。内容散列、帧范围、采样率及核心时间相同，绝对 URL 的容器 UUID 不同。当前活动的 81 个任务已取消且没有结果，旧结果仍存在于数据库。

原始语音笔记自身的全文也仍存在；问题是活动分段任务没有复用旧识别结果，不是原音频或全文从数据库中被删除。

这说明窗口身份依赖运行时路径，导致 App 更新或数据容器搬迁后无法复用已有结果。已实现以下修复：

- 窗口身份包含来源、内容散列、帧范围、采样率、时间、录音中断和配置，排除沙盒 URL。模型窗口划分版本保持不变，已有 ASR 配置仍可匹配。
- 精确匹配旧窗口，优先恢复成功的 ASR/VAD/说话人证据；保留旧行及相关结果，刷新文件位置并使旧工作租约失效。
- 处理结果归属变化时推进版本，拒绝旧的异步派生结果。历史任务因系统失效而取消时，可在来源未被用户取消的前提下重新排队。
- SQLite 升级至 v10，增加可空的语义签名字段。对能精确证明输入相同的旧派生快照，保留主题边界、内容段 ID/版本、标题摘要及检查点；人工分段、回听范围、撤销和删除保护也继续有效。

对**新的原始真机数据库副本**运行最终代码的验证结果：

| 项目 | 恢复前 | 恢复后 |
| --- | ---: | ---: |
| 目标的累计任务数 | 405 | 405，无新增重复任务 |
| 当前活动的成功 ASR 窗口 | 0 | 81 |
| 当前可见转写行数 | 0 | 69,706，散列与历史结果一致 |
| 用户取消标记 | 1 | 1，保持不变 |
| 内容段 | 无活动全文的占位段 | 有完整转写的待处理段 |

再次发现同一来源不会创建任务或推进内容段版本。历史 VAD 中的 56 个失败仍如实保留；恢复过程没有自动启动推理。修复后全量 VAD 的成功结果来自前述独立 Mac 实验，未写回手机数据库。

恢复会为每个窗口选择一份完整、可证明来源的历史结果，不拼接相互冲突的阶段快照。旧主题/摘要缓存仅在能够精确重建旧签名时保留；混杂或不完整的历史不会被猜测为相同内容。

### 3. 当前手机任务已取消，原因尚未确认

数据库源记录 `cancelled=1`。没有证据证明该标志一定由路径变化产生。恢复历史结果与自动重新开始推理是两件事；应保留用户取消语义。

### 4. 录音仍走旧版单文件路径

目标没有 session/chunk/receipt 记录。旧文件本来就不使用分片收据，不能据此判断传输失败。Watch 调试查询超时，未确认其实际安装版本；当前数据不能验证新版本的边录边传流程已在这块 Watch 上启用。
