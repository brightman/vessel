# EurekaRing 原生本地接入 · 2026-10-19

基于 `dev-card`，通过相邻 `br_flutter_plugin_ble` 的 `dev-300` 原生 SDK 接入。没有合并 `dev-healthdata`，没有引入 `br_app_services`。

## 页面和录音流程

- 原硬件原型的结构映射到现有 SwiftUI：顶部连接胶囊、全部硬件、Ring 详情。显示连接状态、真实电量、存储、上次同步和待同步数量。
- 首次主动打开 Ring 页扫描，点击设备完成 SDK 握手并保存绑定。前台恢复时自动重连已绑定设备；用户主动断开后本次进程不自动重连。
- App 开始／结束普通录音；物理录音开始／结束事件更新页面。结束后尝试读取列表并同步。历史录音和离线闪念由「同步录音与闪念」触发。
- SDK 校验 CRC、处理设备文件头 → 本地恢复副本 → 流式 Opus/PCM 转 AAC/M4A 16 kHz、单声道、32 kbps → 保存到现有 VoiceNotes → 原有 Apple/Whisper 本地转写队列。
- 固定 UUID、设备录制时间及 EurekaRing 来源写入已有录音结构；旧 notes.json 的可选字段兼容。设备缺少时间时用同步时间并在详情明确标识。
- Ring 笔记直接出现在一天、记录列表、搜索及原有播放／编辑／转写／总结页面。Ring 流程没有音频上传、账号、服务端会议、数据库或独立“入库”阶段。App 原有自定义 AI 文字总结仍受既有逐次确认流程控制。

## 本地持久化与恢复

- `Application Support/WiseNote/Ring/transfers.json` 保存绑定、设备格式化代次、稳定笔记 UUID、转换阶段与完成回执。恢复目录使用文件保护并排除系统备份；不打印绑定凭据、音频或转写内容。
- SDK 原始传输先完整复制到任务目录；转换成功后才提交现有本地录音索引。保存成功才标记同步完成，随后清理暂存副本；不删除硬件原录音。
- 保存前失败保留可重试材料；重新启动将未完成任务恢复为待处理。保存后、完成回执前崩溃，通过固定 UUID 检测已有笔记，不重复转写。用户删除手机笔记后保留同步回执，避免下次同步把它恢复回来。
- 部分设备文件列表与已知列表合并，不据此删除已知记录或将整机同步标记完成。BLE 逐个文件传输，失败按文件重试；没有承诺 BLE 字节级断点续传。
- 同步与 App 录音、解绑、格式化互斥。断线／重新开始录音使未完成传输停止；已保存的笔记不受影响。后台只使用系统允许的有限延长时间；建议测试时保持前台，不承诺无限后台传输。

## 设备维护

- 断开保留绑定与手机记录。
- 解绑需要已连接、未录音，并在确认后调用 SDK `unbindDevice(deleteAudio: false)`，成功后才清除本机绑定。设备和手机录音均保留。
- 格式化有单独不可恢复确认，说明待同步数量及列表完整性。清空的是设备全部内容，手机笔记保留；成功后更新设备代次，允许同名新录音同步。
- 发出格式化前先持久化“结果待核对”。超时、断线或进程中断后不自动重复命令；「核对上次格式化结果」只查询完整文件列表，恢复同步状态。

## Ring 闪念

- 用户后续扩大范围，增加 Ring 硬件闪念。本地入口识别 `FlashIdea` 和 SDK 约定的 `F` 前缀文件，仍不接入耳机录音、Wi-Fi、打点、云服务或 `br_app_services`。
- 闪念开始／结束由硬件操作；SDK 只有硬件通知，没有 App 发起／结束闪念指令。页面展示本次连接的闪念通知状态及录制中状态，闪念期间普通录音、同步、解绑、格式化互斥。
- 结束后，SDK 已通过 CRC 校验并完成文件收尾的实时音频会先复制到本地恢复目录，再进入原有 AAC/M4A 转换和保存流程；CRC、路径或大小校验不通过不采用实时文件，通过设备列表和 BLE 补同步。离线闪念使用相同流程。旧闪念的迟到结束不会清空下一条的录制状态。
- 实时事件与设备列表共用稳定 UUID 和完成回执，重复通知不新增笔记、不重复转写；重启后恢复未完成的暂存音频。设备列表补充准确的录制时间和时长，但保持任务身份不变。旧日志缺少文件种类时仍按普通录音恢复。
- 保存为现有 `RecordingKind.thought`，进入“一天 → 闪念”、闪念计数、时间轴、搜索、回听和编辑；保留 Ring 来源与原录制时间。
- 自动按现有本地 Apple/Whisper 设置转写，随后使用 Apple Foundation Models 整理核心想法和明确待办。Ring 闪念固定使用本地模型，忽略其他笔记的远程 AI 配置，不读取远程 API Key，也不因模型不可用回退网络。没有 Apple Intelligence 可用模型时保留录音、转写，显示不可用原因，允许手动重试；已转写但整理中断的闪念在重启后继续本地整理。

## 已知 SDK 边界

BRBluetoothLib 3.0.0 握手返回正在录音时，没有恢复 BleAudioManager 的活动录音上下文。App 据握手状态阻止同步／格式化，并提示在硬件上结束录音；结束后同步。不伪造文件名或虚假的录音开始事件。已连接后开始的 App／硬件录音使用正常停止流程。

## 断线后的页面恢复

- 修复“上次格式化结果待核对”优先于连接状态的问题。页面按实际连接状态选择主操作：无绑定时扫描、已绑定未连接时重新连接、已连接且结果待核对时读取文件列表；断线不会停留在一个禁用的核对按钮。
- 主动断开、蓝牙掉线或关闭后，立即清理电量、存储、录制状态、文件列表完整性和进度，释放页面的进行中状态。保留绑定、本机笔记、同步回执以及格式化待核对标记；断线时关闭尚未确认的维护弹窗。
- 异步请求绑定到发起时的连接。旧连接迟到的握手、电量、列表、同步、格式化结果和收尾逻辑不能覆盖新连接或解除其进行中状态。断线取消本地转换，保留恢复副本供重连重试。SDK 初始“未连接”通知不会错误终止首次握手。
- 重连后仍需核对上次格式化的结果，但不会自动重发格式化。录音或闪念进行中不核对文件列表，避免据此误判设备已空。
