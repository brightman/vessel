# 今天的片段：原生开发验证

日期：2026-10-22。范围：iPhone 原生生活时间轴、数据聚合、已有采集位置的派生片段。

## 已实现

### 昨日累计步数

- 前一当地自然日的总步数归档到次日 00:00。详情展示统计日期、起止边界、归档时间和实际刷新时间。
- 前台跨日、HealthKit 更新、回到前台和解锁补刷；查询历史日期时同时读取其前一天。
- 晚到数据更新同一稳定 ID。昨日汇总不影响今日概览，不当作一次步行活动。
- 未读到步数显示待同步，真实 0 步仍保留 0。失败保留并标记旧快照。
- 没有准点后台唤醒承诺；用户正在浏览历史日期时，跨日不会改变所选日期。

### 起床和整夜睡眠

- 按主睡眠结束日期归属，保留午夜前的入睡时间；午睡单列。
- 同来源先组成睡眠段，有明确清醒／卧床连续证据时保留中间长清醒。重叠来源优先选择有分期的来源，再比较睡眠覆盖，不跨设备累加。
- 仍在进行中的样本阻止发布对应结束片段；已结束样本立即显示未确认的起床估计，避免没有重试的固定延迟。
- 展示入睡、醒来、实际睡眠、可读取的清醒与分期。缺失时间不补零，未分期睡眠保留为未分期。
- 可确认当前估计时间为本人起床时间，也可撤销。确认在本机 SQLite 保存，重新载入后保留；起止时间变化后确认失效。
- 无可读取的睡眠质量评分时显示缺失，不生成好坏判断。
- 待同步详情在数据到达后转为主睡眠详情；已移除片段显示失效提示。

### 位置变化

- 仅使用既有录音与照片的采集点，严格大于 50 km，使用直线距离。
- 依据时间排序、源 ID 去重；相邻有效点间隔最多 48 小时，已知精度最多 1 km。照片 EXIF 精度缺失时保留未知并在详情说明；录音精度未知时不生成候选。
- 排除超过 350 m/s 的明显不合理跳点，以及 30 分钟内回到 5 km 范围的 A-B-A 中点。
- 结构化城市名称用于跨城／城内文案；已知不同地区的同名城市加地区区分。解析失败保留坐标与“地点待解析”。
- 两条证据可回看原始照片组或录音。删除派生片段仅保存其抑制 ID，保留原始媒体；原媒体删除或坐标修正后重新计算。
- 地址缓存兼容旧数据；仅在既有地点授权及前台条件下，用 Apple 地图解析当天和明确关联的跨日证据。未新增服务器或持续定位。

### 展示和存储

- 首页“全部”保留最新四条预览；“生活”展示当天全部生活条目。
- 原始日步数用于概览，昨日归档用于时间轴；主睡眠用于概览，午睡不会替换主睡眠。
- 新增 `life_moment_metadata` 附表及独立域迁移。未更改共享数据库 schema 版本，不影响并行开发的录音会话表。
- 更新关键控件的中／英／日文本。新生活详情继承现有外观、Sheet 和删除交互。

## 真机待验

本轮未安装或自动操作原生模拟器界面，未读取真实健康数据、实际用户坐标或调用外部 AI。编译和本机测试通过不等于真机交互与后台投递已验收。

1. 在设置启用 Apple 健康步数／睡眠读取。查看昨日总数是否与健康 App 的统计日一致；回到前台检查实际更新时间。
2. 佩戴能提供睡眠数据的设备过夜；核对跨午夜入睡、醒来与时长。确认起床，重启 App 后检查，再撤销。
3. 录制／拍摄两处相距超过 50 km 的记录，允许地点；等待地址解析，检查两个源记录的回看和删除派生条目。
4. 深色／浅色、大字体、VoiceOver、长城市名称、左划删除和底部详情切换需人工验收。
5. 测试前台过午夜、后台过午夜再打开、锁屏后解锁补刷。系统投递时机与实际可用睡眠分期依设备及数据来源而定。

睡眠主段选择、分段间隙与位置过滤均为当前产品规则，不能证明实际离床时间、行程路线或停留时长。
