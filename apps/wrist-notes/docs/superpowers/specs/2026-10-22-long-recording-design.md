# WiseLife 长录音：分片保存、分段处理与内容时间轴

日期：2026-10-22。

状态：用户已接受底层每 5 分钟保存一个文件、界面仍按完整录音和内容片段展示。本文将讨论中的方案整理为工程设计；不是已实现功能清单。本轮仅更新文档。

## 1. 目标与约束

- 原始文件每 300 秒一个；最后一个文件允许不足 300 秒。
- 一次手动开始到结束为一个录音会话，文件名使用 `sessionID_0000.m4a`、`sessionID_0001.m4a`，序号另存为整数。
- 当前工程最低版本保持 iOS 26.0、watchOS 10.0；真机验收使用用户的 iPhone 16 Pro 和 Apple Watch SE。
- 音频以单声道、16 kHz、约 32 kbps AAC 保存；采集设备原生采样率在后台写入队列中转换。
- Watch 保存与传输，iPhone 执行转写、VAD、说话人识别、内容整理、检索和总结。
- 默认使用本地存储和端上模型；模型不可用时给出状态，不自动启用云端服务。既有用户配置的云模型仍遵循原有明确选择和发送确认机制。
- 用户已有录音、文字、手动标题、说话人标注和数据保护策略保留；原音频不因自动分段而重写或删除。
- 5 分钟物理文件、模型输入窗口、时间轴内容片段分别定义。一个内容片段可跨文件，一份文件可被多个内容片段引用。
- 自动合并限定同一次录音会话。用户确认过的内容边界保留。

## 3. 分三个阶段交付

### A：可靠录音、同步与回听

交付 5 分钟文件轮换、恢复、校验、逐片同步、一次录音的聚合状态和跨文件播放。新会话保持一条时间轴记录，详情可展开已保存分片及异常区间。新分片会话的自动推理保持待处理状态，避免落入旧的整文件路径；旧笔记保持现有处理行为。

### B：有界推理与无人声分段

交付 Apple ASR/Whisper 小窗口转写、VAD、跨文件 600 秒无人声边界、说话人跨窗口映射、持久化进度与片段级全文/总结。只有有界说话人流水线通过真机内存测试，才解除长录音说话人识别的临时限制。

### C：语义整理与检索

交付话题变化检测、跨文件内容合并、用户拆分/合并及撤销、片段时间轴、检索和 AI 来源回溯。B 的基础规则在语义模型缺失时仍可运行。

三阶段共享以下数据和时间契约。A 有独立的可靠性验收，不意味着 B/C 已完成。

## 4. Watch 连续采集与文件封口

### 4.1 轮换

采用一个持续运行的采集引擎和串行文件写入队列。音频回调只向预分配、有容量上限的缓冲池提交采样；格式转换、编码、磁盘写入、校验和清单更新在回调外完成。禁止逐回调创建无界 Task 或无限缓存。

写入按实际采样帧计数达到 300 秒后切换目标文件，同一个输入缓冲可以拆给前后两个文件；采集引擎保持运行。AAC priming/padding 单独核对，播放采用有效帧范围，不能把编码填充累计为录音时长。

写入中路径：`sessionID_0000.partial.m4a`。关闭并释放写入器、读取有效帧信息、校验可读取后，再发布为 `sessionID_0000.m4a`。该文件发布后不可变，允许同步；正在写入的文件不进入传输队列。

缓冲池上限初始按两秒输入音频设计；达到上限时保存可封口部分、记录中断并停止，避免静默丢帧或继续显示正常录音。实际池大小和 Watch 峰值内存通过 A 的设备实验确定并写入验证报告。

### 4.2 清单与恢复

Watch 每个会话有原子写入的清单，每个分片有可独立读取的 sidecar。清单包含会话状态、最后分片序号、分片摘要及 ACK；不能仅依赖一份全局 pending.json。

封口顺序：关闭音频 → 验证 → 发布最终文件 → 写 sidecar → 更新会话清单 → 排队传输。文件系统与元数据不能组成一个跨系统事务，因此每一步都必须可重放：

- 最终文件存在、sidecar/清单缺失：扫描已知会话和安全文件名补建记录。
- sidecar 存在、总清单损坏：隔离坏清单，从 sidecar 重建；继续扫描其他会话。
- partial 文件可读取：保留可验证部分并标注恢复；不可读取：保留原件及失败记录，禁止自动删除或虚报成功。
- 进程被终止：下次打开把未完成会话标记为中断，保留已封口文件。不能承诺被系统终止后继续录音。
- 中断、音频路由变化、存储写入失败：结束当前连续区间，标注原因；恢复时追加新文件和间隙记录。
- 用户停止恰逢轮换：由一个状态机串行处理，最后一个非空文件只封口一次。

首次实现不自动清理已确认文件。只有 iPhone 已校验且提交 SQLite 后，Watch 才能标记已保存；用户删除或后续明确的保留策略才能清理 Watch 副本。存储不足时提前提示并有序停止，禁止为继续录音删除未确认文件。

## 5. 时间与标识契约

每个物理分片有独立 chunkID，同时具有 sessionID 和 ordinal；三者在重试时稳定。

- `capturedAt`：现实时间锚点，含采集时区信息。
- `sessionStartOffset`：相对本次会话时间轴的秒数，由采集时钟推导；不通过文件序号乘 300 推算。
- `frameCount / sampleRate`：实际可播放时长。
- `discontinuities`：采集缺口、格式变化和中断的时间范围与原因。
- `recordedDuration`：可验证音频的累计时长。
- `elapsedDuration`：开始到结束的时间跨度，可能包含中断。

两种时长分别存储；录音时长默认展示实际可播放时长，缺口另行提示。修改系统时间、跨午夜和夏令时不改变音频内部帧顺序。地点为具体采集时刻的位置快照，不能把开始位置解释为全程轨迹。

## 6. 传输协议 V2

### 6.1 能力协商与兼容

- 新 iPhone 接受旧 Watch 的 V1 文件，旧笔记可映射为一个会话内的一份文件；原路径和 ID 保留。
- 新 Watch 开始 5 分钟分片保存。只有当前配对 iPhone 明确声明支持 V2 后才发送 V2 文件；旧 iPhone 保留本地待同步并提示更新，不让旧接收器把每份文件误当一条独立笔记。
- 能力缓存绑定当前配对关系，换表/换手机后重新协商。闪念继续走现有单文件协议。

### 6.2 不可变文件与收据

每份文件携带 V2 编码的 descriptor：版本、sessionID、chunkID、ordinal、会话开始时间、分片时间锚点、相对偏移、有效帧数、采样率、字节数、SHA-256、来源硬件、可选位置和中断信息。所有路径由接收端构造，拒绝目录穿越、符号链接、非有限值和无效时间范围。

接收流程：

1. 在 WCSession 接收回调返回前，将临时文件移至持久 inbox，并原子写入 descriptor。
2. 在串行工作队列流式计算校验和、检查文件头及有效帧范围；音频检查失败保留隔离副本，原发送端保留原件。
3. 将文件移动至固定目标位置，在 SQLite 事务中提交会话、分片和收据。
4. 提交成功后发送包含 sessionID、ordinal、chunkID、SHA-256 的 ACK。ACK 丢失时，同一份文件重传可以返回已有收据。
5. 文件成功保存与 ASR 完成分别记状态；ACK 不等待模型处理。

唯一性使用 `UNIQUE(session_id, ordinal)` 及 chunkID。重复且内容相同幂等成功；同一身份校验值不同视为冲突，保留已确认版本及异常来件，不覆盖。乱序到达允许入库，但缺失序号必须可见。

会话结束使用单独可重试的 manifest 消息，包含最终 ordinal 和会话修订号；最后一份文件的 ACK 不能代表会话结束。收到结束消息且所需分片全部保存，才能标记整次录音已同步。

WatchConnectivity 是系统调度的后台传输。无连接不影响继续本地保存。待同步条数按会话统计，详情显示已收分片/总分片；总数未知时展示“录音中”。仅保存收据改变最近同步时间。

数据库或文件因锁屏保护不可用时保留 inbox/发送端原件，解锁后重试。完整保护策略不降低。已有 SQLite page-in SIGBUS 属独立问题，需在锁屏导入验收中单独跟踪，不能仅凭新增队列宣布解决。

## 7. iPhone SQLite 与媒体存储

音频放应用文件目录；SQLite 放元数据、处理结果、索引及关系。

| 表 | 关键字段与约束 |
| --- | --- |
| recording_sessions | id、开始/结束、时区、设备、状态、最终序号、修订号；可选 legacy_note_id 唯一 |
| recording_chunks | id、session_id、ordinal、文件名、时间锚点、offset、frame_count、sample_rate、bytes、sha256；会话序号唯一 |
| recording_gaps | session_id、起止偏移、原因；区别无语音和缺失音频 |
| recording_receipts | 分片身份、hash、pairing_id、保存时间；用于耐久 ACK 和重放 |
| audio_processing_jobs | 输入文件 hash、范围、阶段、模型/语言/算法版本、状态、重试次数；输入任务键唯一 |
| audio_transcript_spans | job_id、源分片、时间范围、文本、说话人；按 session/时间索引并分页 |
| audio_activity_intervals | 已分析范围、speech/noSpeech/uncertain；与任务完成状态分开 |
| content_segments | id、session_id、时间范围、标题、总结、revision、draft/final、manual_boundary |
| content_segment_ranges | segment_id、chunk_id、起止有效帧、顺序；外键关联 |

A 只创建前四张表及必要投影，B/C 按各自迁移新增其余表。迁移必须事务化、可重开，不回退用户已有 schema。不要在每次进度更新时重编码数万条转写片段到一个大 JSON payload。

一个文件可以被多个内容片段引用。删除内容片段仅改变派生记录；删除整次原始录音是独立显式动作，采用 tombstone + 文件清理重试，并清除关联全文、向量与 AI 缓存。晚到的传输、转写和 AI 结果必须检查 tombstone 与 revision，不能复活用户删除的数据。

## 8. 有界处理、VAD 与语义边界

### 8.1 处理窗口

输入窗口上限初始为 300 秒，边缘额外读取最多两秒上下文；遇到资源不足缩小窗口并降低并发。ASR/说话人模型重任务同一时刻仅一个，采样缓冲用完释放。300 秒输入上限不是模型峰值内存保证，需要分别测量 Apple ASR、Whisper 和 SpeakerKit。

旧的多小时文件通过 AVAudioFile 按范围读取，也进入同一流水线。禁止先把原文件完整解码，再切数组。跨窗口文本以源时间戳和范围归属去重；重复口头表达不能仅凭相同文字被删除。所有时间戳映射回原音频范围。

任务完成和结果在同一 SQLite 事务中保存。退出后重跑未提交窗口，保留已提交窗口；模型/语言变更产生新版本，不覆盖人工修改。任务缺失、失败、未下载模型、用户取消和成功但无语音必须区分。缺少模型不自动下载，也不自动转到云端。

说话人编号仅在单窗口内有意义；通过会话级声纹/特征匹配建立跨窗口映射，不直接把不同窗口的 speaker-1 当作同一个人。合并证据不足时保留未知。

### 8.2 600 秒无人声规则

必须拥有连续、成功分析的音频覆盖，且 VAD 确认无人声；区间可以有环境音或音乐。ASR 空结果本身不证明无人声。有 ASR 文本但 VAD 判无人声时标记冲突并复核，不能直接作为高置信边界。

按会话时间轴跨文件累计，连续无人声达到 600 秒形成边界；前后语音各保留最多两秒前导/尾音，并裁到合法可用范围。缺失文件、中断和处理失败不计入无人声。原音频仍保留，普通时间轴默认折叠确认无语音的区间。

### 8.3 内容整理

文件边界不直接产生内容边界。时间连续、语义连续的候选片段可以合并；明显话题变化可形成建议边界。600 秒无人声边界、已知录音缺口和不同 session 默认不自动跨越。证据不足保留现状，提供手动操作。

语义模型只读必要的边界附近转写和前段摘要；超长片段的总结按小段总结后再综合，模型上下文受限时继续层次汇总。生成结果携带源范围及 revision，人工编辑期间到达的旧结果丢弃。

会话录音/接收中只调整未定稿的尾部内容，已手动确认边界冻结。结束并处理完成后定稿；显式重新整理创建新派生版本，可撤销。原始文件保持不可变。

## 9. 时间轴、播放与 AI 使用

A 展示一条会话记录，展开分片与缺口；B/C 展示内容片段，同时提供“查看完整录音”。播放计划是有序 `(chunkID, startFrame, endFrame)`，seek、波形和字幕通过同一映射定位。缺口明确提示；不能用静音填充伪装为原始录音。跨文件实际播放衔接需要真机验证 AAC 填充与调度行为。

内容片段跨午夜时按每个本地日期的交叠区间投影到各日，保持同一 segmentID，日期内显示该日范围及续段标记；完整详情仍可回听全部片段。每日统计只累计该日交叠范围，跨日检索以 segmentID/源范围去重。

FTS 用于准确文本检索，SQLite Vector 用于语义候选召回；向量相似度不是确定内容合并的唯一依据。问 AI 的证据指向内容片段及音频范围；已有父会话与子片段不得作为两份独立证据重复计数。VAD 仅说明检测到语音活动，不证明某人参与或环境事实。

## 10. 验收与已知边界

A：连续录制跨至少三次文件边界，人工停止、录音中切后台、锁屏、路由变化、强制终止、存储写失败、清单损坏、乱序/重复传输、ACK 丢失、旧版兼容、删除后重传；所有已封口原文件可恢复且不重复显示。固定采样输入验证分片有效帧总和、顺序与原始输入一致；SE 实际麦克风验证边界无明显丢字并测量间隙，不把模拟器结果作为真机连续采集证据。

B：构造 599/600/601 秒无人声，跨文件同一句话、失败窗口夹在无语音区间、缺失文件、纯环境音、不同语言、重启恢复；验证恢复只重做未提交窗口。对至少 6.5 小时代表性录音记录峰值内存和每窗口完成后的内存，确认不会随总时长持续增长；较长原件仅在本机测试，不进入仓库。

C：跨文件同话题、短停顿换话题、600 秒后同话题、人工编辑与异步结果冲突、合并撤销、跨午夜、引用跳转、父子检索去重。生成总结和建议只能引用实际有证据的内容。

上线门槛：A 真机连续采集/恢复通过，B 实际长文件内存回归通过，旧数据兼容回归通过；未完成时保持现有保护和功能可用状态说明。电池、存储、系统强制终止和录音权限可能限制时长；5 分钟分片降低未封口风险，不承诺任何中断情况下零损失或持续录音。
