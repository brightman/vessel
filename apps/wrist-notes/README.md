# WristNotes

一套本地优先的 iPhone 与 Apple Watch 语音笔记原生 App。手表录音并保留待传文件；iPhone 收到音频后保存原文件，在设备上转写、编辑，默认使用 Apple 本地模型总结。可选用户自有的 OpenAI 兼容服务生成总结；不使用 Vessel API，也不需要自建中转服务器或 App 账号。

Watch 单按钮界面方案见 [`prototype/watch-recorder.html`](prototype/watch-recorder.html)。轻点按钮开始或结束长录音，按住约 0.45 秒进入闪念并在松手时保存，上滑可取消。SwiftUI 已实现同一套单按钮交互、录音列表、上传状态和左划删除；具体核对记录见 [`verification/README.md`](verification/README.md)。

iPhone 列表与详情界面方案见 [`prototype/iphone-notes.html`](prototype/iphone-notes.html)。详情页的音频下方可切换“总结 / 全文 / 综合分析”；还可演示搜索、编辑、播放控件、重新转写、生成总结与导入入口。SwiftUI 已对齐这套列表和详情布局，连接现有本地播放、编辑、转写和总结能力。网页中的内容是演示数据；App 正常启动不会添加示例笔记。

**2026-10-19 原生设置接入：** 首页右上角提供真实 Watch 通信状态和设置入口。设置支持深色/浅色/跟随系统、Apple 转写语言、音频导入，以及 Apple 本地 AI / 自定义 Chat Completions 模型。自定义模型先真实测试，再保存，随后用于笔记总结。Whisper 显示“尚未接入”，不能选用。实现与验证记录见 [`verification/settings.md`](verification/settings.md)。

**2026-10-19 会议心率与综合分析：** 详情页新增心率时间轴、“综合分析”标签和时间戳原文回听。设置 → 会议心率中申请只读 HealthKit 权限。不开启体能训练，iPhone 在收到录音、打开详情、回到前台和健康数据更新时查询录音区间；只保留实际 Apple Watch 样本，不补造连续曲线。短录音可能没有样本，健康同步也可能延迟。

## 会议心率与综合分析

**运动上下文与心境扩展（2026-10-19）：** 心率查询保留 `HKMetadataKeyHeartRateMotionContext` 原值，区分“采样时活动中 / 此前至少 5 分钟静止 / 未知”，复用已有心率读取权限。图表选中样本、E 证据和综合分析均包含上下文；未知不表示无活动，不能把单个采样点的状态推广到整个区间，也不能判断坐姿、专注或说话人。

设置 → 会议健康数据新增独立的“接入本人心境记录”只读开关，读取 `HKStateOfMind`。当下感受只查询并保留录音区间内的记录；全天心情查询录音所在日的记录，以查询时手机时区确定并保存日边界，仅作背景，即使记录时间在录音内也不匹配话语。保留愉悦度、感受标签、关联因素及来源；支持 iPhone 健康 App、手表正念 App 等来源，不当作传感器测量。此版不新增心境写入或手表录入界面。

综合分析按时间选择最多 6 条当下感受、2 条全天背景作为 M 证据；只有与当下感受记录时间重合的转写片段可并列展示。全文不得从心率、静止或 HRV 推断情绪；本人记录须明确标为主观自报，“工作”等关联因素不能证明会议因果。关闭心境清除本地心境及分析，保留心率/HRV；关闭心率清除心率/HRV 及分析，保留独立心境。心境单独开启时也可回填和分析。自定义 AI 的逐次确认已包含运动上下文、心境愉悦度、标签、关联因素及相对时间；不发送来源名称、HealthKit UUID、设备标识、时区标识或音频。

**HRV 扩展（2026-10-19）：** iPhone 端新增 `.heartRateVariabilitySDNN` 只读授权、查询及后台变更观察。设置 → 会议健康数据中可独立开启“接入 HRV（SDNN）”；已有心率授权用户不需关闭原功能。不开启体能训练、不触发测量、不从 BPM 估算 HRV。手表端采集代码及权限保持原状。

HRV 按完整测量窗口保存，以毫秒显示；查询与录音相交的样本，图表只裁剪可见时间，不改写数值或原始测量时间。跨录音边界的窗口会明确标注，不能全部归因于会议；零时长样本标注窗口时长未知。会议内无样本时显示缺失，不插值、不从心率推算。

综合分析加入 HRV 采样事实和 V 编号证据，按时间均匀选取最多 6 个窗口逐段复盘，并结合同期原文及心率 E 证据；全部 HRV 样本可在时间轴明细中查看。不将 SDNN 与 RMSSD 混同，不依据 HRV 高低判定情绪或医学异常。自定义 AI 的逐次发送确认已包含 HRV 数值、测量窗口和跨边界相对时间，仍不发送音频、HealthKit UUID 或设备标识。

时间轴当前为 schema 4，读取 schema 1/2 时保留已有心率、HRV、时间戳和转写绑定，旧样本缺少的运动上下文按未知处理，旧分析失效后可重新生成；schema 3 的健康数据及有效分析继续保留，新增发言人字段默认为空。运动上下文、HRV 或心境记录变更/删除会使分析失效；单独关闭 HRV 清除其缓存和综合分析，保留心率和心境。关闭心率接入同时清除 HRV，所有健康衍生数据继续保存在排除备份且受文件保护的时间轴目录。

1. 更新 App，iPhone 设置 → 会议健康数据中开启“接入 Apple Watch 心率”，需要 HRV 时再开启“接入 HRV（SDNN）”，完成系统授权，再用手表录制一场会议。系统授权流程完成不代表读取权限已授予；空结果显示暂无可用数据。
2. 录音传到手机后查看详情，心率点与音频共用相对时间轴。点按图表、证据区间或时间戳原文可定位回听；拖动播放滑块也可定位。心率更新失败时保留上次数据并显示提示。
3. 进入“综合分析”点击生成。使用当前 AI 设置，结合转写、已有总结、采样事实和带时间戳的同期原文，复盘会议主题、决策、行动项、同期变化及供本人确认的问题。没有总结也可分析，不自动另行发送普通总结请求。
4. 筛选同一来源相邻采样相差至少 10 bpm、间隔不超过 10 分钟的区间，最多选变化最大的 8 个，并列出起止时刻、采样值及原文。这是复盘筛选规则，不是医学异常阈值。样本之间的变化时刻和持续时间未知，不能断言“某句话导致某种情绪”。发言人编号不能确定真实身份或谁是手表佩戴者，也不能确定佩戴者当时在听或在说。
5. 自定义 AI 每次综合分析前单独确认服务地址、模型和发送范围：本篇转写、总结、相对时间、采样值；不发送音频、HealthKit UUID 或设备标识。普通总结请求仍只包含文本。Apple 本地模型不可用时直接显示错误，不自动切换远程服务。
6. 心率、转写时间段和分析存在 `Documents/VoiceNotes/Timelines/<UUID>.json`，使用文件保护并排除系统备份。心率样本按 HealthKit UUID 去重，每次成功查询替换完整录音窗口，以反映原始数据删除。关闭心率接入清除本地心率和分析，保留音频和转写，不修改健康 App 数据；删除笔记会同时删除对应时间轴。
7. 新手表录音携带音频零点、结束时刻、单调时钟和实际文件时长。时钟跳变或时长不一致时不自动匹配健康数据。旧录音、外部导入和崩溃后仅从音频恢复的条目没有可靠时钟，当前不自动关联心率。重新转写可为旧录音补充文字时间戳，但不能恢复录制时钟。
8. 心率或内容更新后旧分析失效；手动编辑全文会清除旧的原文时间戳。每组时间戳还绑定对应转写文本，避免跨文件保存中断时出现错误关联。修改标题不使分析失效。

本地测试新增时钟、样本去重与删除、区间证据、失效规则和时间轴持久化检查；模拟器集成验证使用独立 Bundle ID、合成样本、本地 HTTP fixture 及内存测试 Key，不读取用户健康数据。真实采样密度、健康同步延迟和本地模型分析质量仍需真机验收。

## 本地发言人分段

全文默认提供“分段回听”，显示发言人及起止时间，点击段落定位播放；可筛选某位发言人、为本条录音内的编号改名，也可切换“编辑全文”。Apple Speech 继续负责转写和真实时间范围，另由固定版本 FluidAudio 0.17.7 的 Community-1 离线模型按声音区分发言人，再对齐文字。不会用大语言模型猜发言人。

首次点击“区分发言人”会联网下载约 22 MB 模型资源并在本机加载。模型下载由 Hugging Face 提供，录音仅在 iPhone 读取和处理，不上传。模型缓存排除备份；处理后只保存本条录音的时间区间、匿名编号和用户确认的名称，不保存声纹向量或跨会议人员库。开源许可和模型署名可在“设置 → 语音转文本”查看。

手动启动后，“转写后自动区分发言人”随之开启，可在设置中关闭；已有录音仍需手动启动。首次下载及长录音分析时建议保持 App 在前台、手机解锁。支持取消；当前推理步骤结束后停止。失败或取消会保留之前已保存的结果。

新转写保留 Apple 原始时间范围，旧录音可使用已有较粗的时间片段；跨发言人边界、无法归属和多人重叠的文字会显示待确认，不按字数伪造时间。旧时间戳过粗时可重新转写以改善对齐，声音相似、远场噪声及抢话仍可能造成误分。编号只在当前录音内有效，不能识别真实姓名或自动判断谁佩戴了手表。

结果随时间轴 schema 4 持久化并绑定音频文件、时长及转写全文。手动编辑全文会清除旧时间戳和发言人结果；仅改标题保留结果。重新区分会重建编号并清除自定义名称。原始音频不改写。发言人变化会使已有综合分析失效，但当前综合分析尚不推断个人身份、佩戴者角色或各人的健康状态。

## 设备与系统

- 开发环境：Xcode 26.3。
- iPhone：最低 iOS 26；当前已安装启动至 iPhone Air（iOS 27.0）。
- Apple Watch：最低 watchOS 10；当前已安装启动至 Apple Watch Series 11（watchOS 26.6）。

## 打开与安装

1. 用 Xcode 打开 `WristNotes.xcodeproj`，选择 `WristNotes` scheme。
2. 在 iPhone 和 Watch 两个 target 的 **Signing & Capabilities** 中选择自己的 Team。若 Bundle Identifier 被占用，一起修改 iPhone ID、Watch ID 与 Watch `Info.plist` 中的 `WKCompanionAppBundleIdentifier`，再运行 `ruby scripts/generate_project.rb` 前先同步修改生成脚本；重新生成工程会覆盖 Xcode 中直接改的项目设置。
3. iPhone 解锁并信任 Mac，开启开发者模式；确认 Apple Watch 已与该 iPhone 配对，在 Xcode 的设备列表中可选。先在 iPhone 上运行 `WristNotes`，再确认手表 App 已安装。Xcode 若无法看到手表，检查配对、同一 Apple ID、蓝牙/Wi-Fi 和设备支持组件。
4. 首次轻点手表红色按钮授权麦克风。闪念首次授权时，松开后再次按住按钮，触觉反馈后开始说话。
5. iPhone 首次转写所选语言可能要通过 Apple 的 `AssetInventory` 下载语音资源。下载完成后可断网测试转写。下载是 Apple 系统资源请求，App 不向自建服务上传音频。

模拟器验证使用 iPhone 17 Pro（iOS 26.3）与 Apple Watch SE 3 44mm（watchOS 26.2）；另已完成上述两台真机的签名、更新安装和启动。长会议录音、健康采样与真实模型质量仍需实测。

## 使用流程

1. 手表轻点红色按钮开始长录音，再轻点结束；按住约 0.45 秒进入闪念，触觉反馈后说话，松开保存，上滑再松开取消。闪念不足 0.3 秒不保存；长录音期间长按不会误停。
2. 手表列表显示名称、开始时间、时长和“未上传 / 已上传”。“已上传”只在手机确认保存后显示；本地条目与音频仍保留，可左划删除。列表底部提供重试入口。
3. iPhone 列表支持搜索与左划删除；导入音频、转写语言和外观移至右上角设置；详情页可播放录音，并在播放器下方切换“总结 / 全文 / 综合分析”。全文可编辑，支持保存、重新转写和生成总结。修改全文会使旧总结失效，修改标题不会。
4. 音频和笔记分别存于各自 App 沙盒。卸载 App 可能删除本地数据；当前版本没有云备份、跨设备同步或导出功能。

模拟器的 WatchConnectivity 不支持文件传输和后台用户信息传输，因此模拟器构建用可达时的分片消息传送录音，并在 iPhone 保存后回执；真机仍使用 `transferFile` 与 `transferUserInfo`。模拟器验收时需让两端 App 保持运行。

## AI 模型配置

1. iPhone 首页右上角设置 → AI 模型 → 自定义模型。
2. 填写服务提供的模型 ID、Base URL（例如 `https://api.example.com/v1`，不带 `/chat/completions`）及 API Key。
3. 点击“测试连接”。测试仅发送固定短文本，测试通过后“保存”可用；修改任一字段需重新测试。返回会放弃未保存修改。
4. 进入一条笔记 → 总结 → 生成总结／重新生成。只发送这条笔记的全文，不发送音频。长文本分段压缩后汇总。
5. 切回 Apple 本地模型后在 iPhone 上总结。模型不可用或失败时显示错误，不自动切换服务。已有笔记和总结不因更换配置被删除。

Key 保存在 iOS Keychain（仅本设备，解锁后访问），普通设置存在 UserDefaults。连接使用 HTTPS；仅允许本机 loopback 使用 HTTP（真机 localhost 指 iPhone 本身，不是 Mac）。不跟随 HTTP 重定向，需直接填写最终服务地址。支持普通 Chat Completions 文本响应，不包含其他厂商专有协议或语音 API。

## 真机验证清单

用户于 2026-10-19 反馈：Watch → iPhone 传输已在另一 agent 修复，真机 ASR 测试通过。以下长时录音、断连恢复等仍是扩展验收场景，本次新增设置不会重新实现传输和 ASR。


- 手表长录音：录制 30 分钟以上，分别测试熄屏、抬腕、切换表盘、来电/通知中断；确认时长、文件可播放及电量表现。后台能否稳定持续录音以实测为准。
- 闪念：测试首次权限弹窗、短按、按住后松开、权限拒绝，以及长录音与闪念切换。
- 传输：录音后断开手机连接，确认手表待传文件仍在；重连后核对手机音频；重复传输只生成一条笔记；手机保存确认前手表不删文件。
- ASR：分别用普通话短录音和长录音，安装语音资源后开飞行模式重试；核对识别内容、耗时与失败提示。
- 总结：确认设备 Apple Intelligence 已开启且中文模型可用，再分别测短文本和长文本；核对总结是否忠实原文。不可用时验证音频、文本仍能访问。
- 持久化：杀掉并重开两端 App，检查笔记、音频、待传队列与处理状态。
